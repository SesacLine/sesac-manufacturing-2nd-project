판정이 된다. LLM이 잘못된 문장을 써도 판정에는 들어오지 않는다.

`reject_token`(고정 사유 코드).

## 1. 입출력 계약 (필수)

이 노드는 그룹 하나마다 1회 실행된다. 아래 키는 그룹 단위 상태(`GroupState`) 기준이다.

### 1-1. 입력

| state 키 | 타입 | 채우는 주체 | 없으면 / None이면 |
|---|---|---|---|
| `hypotheses` | `list[Hypothesis]` | ⑤ build_hypotheses | 빈 리스트면 채택 0건 → status `insufficient_evidence` |
| `mcp` (주입, **미사용**) | `MCPClient` | `deps.py` | 받기만 하고 호출하지 않는다(재조회 안 함) |

- **전제조건**: 각 가설의 `evidence`는 ⑤가 옵션 A로 채워 둔 상태다(수치는 전부 도구 출처).
  `investigated`(조사 여부) 마커가 실려 있다.
- **가정이 깨지면**: `evidence`에 특정 키가 없어도 `.get()`으로 `None` 처리한다(관대한 읽기).
  대부분의 규칙은 값이 `None`이면 "통과" 또는 "보류"로 안전하게 흐르므로 예외를 던지지 않는다.

### 1-2. 출력

| state 키 | 타입 | 비고 |
|---|---|---|
| `critic_result` | `CriticResult` = `{status, accepted, rejected}` | `status`는 `accepted` 또는 `insufficient_evidence` |

**하위 노드(⑦)가 믿어도 되는 불변식**:
- **fab 재조회 0회.** ⑥ 구간에서 MCP·LLM 호출이 전혀 없다 — 실측으로도 0회.
- **`accepted`의 순서 = 입력(⑤) 순서를 그대로 보존한다.** ⑤가 1위로 올린 가설이 `accepted[0]`,
  곧 대표원인이 된다(순위를 바꾸지 않는다).
- 기각·보류된 행마다 `reject_token`(고정 코드)과 `reject_reason`(표시용 문구, #45로 영문)이 붙는다.
- `status`는 채택이 1건 이상이면 `accepted`, 0건이면 `insufficient_evidence`다. **재시도 없음.**
- **내가 건드리지 않는 키**: `hypotheses`(순서·내용 그대로 통과), `final_response`.

### 1-3. 새로 도입/변경한 필드

| 필드 | 타입 | 왜 필요한가 |
|---|---|---|
| `critic_result` | `CriticResult` | ⑦ 응답 카드가 읽는 판정 결과(채택/기각/보류 3분류 + status) |
| `reject_token` | `str` (enum) | ⑦이 프론트 표시값(verdict)을 매핑하는 **유일한 키**. 자연어 매칭 금지 |
| `reject_reason` | `str` | 사람이 읽는 기각 사유 문구(표시용). 판정 로직에는 안 쓴다 |

## 2. 실패·경계 케이스 계약 (필수)

| 상황 | 이 노드의 동작 | 하위 노드(⑦)가 보게 되는 것 |
|---|---|---|
| 입력 `hypotheses`가 빔 | `accepted=[]`, `rejected=[]`, status `insufficient_evidence` | ⑦'가 "판단 불가" 카드 |
| `evidence` 필드 결측 | `.get()`으로 `None` 처리 → 규칙별 안전 분기(반대근거 None이면 기각, drift None이면 미조사 시 보류) | 정상 판정 흐름 |
| 외부 호출 실패 | **해당 없음** — 이 노드는 MCP/LLM/파일을 호출하지 않는다 | 항상 결정적 |
| 채택 0건 | status `insufficient_evidence`, 재시도 안 함 | ⑦'가 "판단 불가" 카드 |

- **예외를 던지는 경우**: 없다. 순수 함수라 관대한 읽기로 예외 없이 판정까지 간다.
- **타임아웃·재시도**: 없음 — 외부 의존이 0이라 지연·재시도 개념 자체가 없다.

## 3. 내부 플로우

가설 1건마다 아래 규칙을 **위에서부터** 검사한다. **처음 걸리는 규칙이 판정을 정하고**, 끝까지
아무것도 안 걸리면 채택한다. 전부 결정론이며 fab 재조회는 없다.

```
가설 1건
 ① 시간정합     정비 시각 > 결함 시각 (정비가 결함보다 늦음)?     → P2 rejected   ← 함정 기각 지점
 ② KG 메커니즘   tier == 근거없음?                              → P5 judge_unknown (보류)
 ③ 미조사       investigated == False?                        → judge_unknown (보류)
                                                                 반자동 SEMI_AUTO_PENDING /
                                                                 자동 폴백 NOT_INVESTIGATED
 ④ faithfulness 자동 tier + 조사됨인데 drift 판정이 비어 있음?     → P4 rejected
 ⑤ 반대근거     normal_ratio를 수집 안 함(None)?                → P3 rejected
 ⑥ 인과 서명    공통률 1.0 AND KG 예상 방향과 drift 방향 일치?    → 아니면 P6 rejected  ← 환각 억제
 else                                                          → accepted

status = accepted 1건 이상 → "accepted",  0건 → "insufficient_evidence"
```

판정은 **3분류**로 나뉜다:
- **accepted** — 증거가 지지함.
- **rejected** — 증거가 반박함 (P2·P3·P4·P6).
- **judge_unknown** — 조사 못 했거나 확인 불가라 판단 보류 (P5·미조사). **기각과 다르다.**

순서에 두 개의 불변식이 박혀 있다:
- **보류 조건(②③)이 채택 게이트(④⑤⑥)보다 앞이다** — 0724 재배치 → §4-2.
- **⑥이 체인 맨 뒤다** — 앞에 두면 미조사·근거없음 행이 보류가 아니라 P6 기각으로 빠져
  "안 봤다 ≠ 기각" 원칙이 깨진다 → §4-5.

## 4. 설계에서 중요하게 고려한 것 (필수)

### 4-1. 판정에 LLM을 쓰지 않는다 — ⑤ evidence만 읽는다

- **문제**: 판정 단계에 LLM이 개입하면, `evidence`에 없는 값으로 채택·기각할 여지가 생긴다(환각).
  실행마다 결과가 달라져 평가 재현성도 깨진다.
- **선택**: 규칙 기반 결정론으로 하고, **fab을 다시 조회하지 않고 ⑤가 채운 `evidence`만** 읽는다.
  ⑤가 모든 수치를 도구 반환에서 계산해 두었기(옵션 A) 때문에 이 방식으로도 사실 근거 판정이 된다.
- **대안과 기각**: LLM으로 판정(LLM-judge) → 재현 불가, "evidence만 읽는다"는 성질이 무너짐.
- **되돌릴 조건**: ⑦에 LLM이 붙어 "문장 단위 사실 대조"가 필요해지면 **별도 층**으로 설계한다 —
  지금의 규칙 게이트(재조회 없음)는 그대로 둔다(§8).

### 4-2. 시간역전은 맨 앞, 보류는 채택 게이트보다 앞 — 규칙 순서의 의미 (0724 재배치)

- **문제 1(시간정합이 맨 앞인 이유)**: `반자동` 후보는 지금 항상 "미조사" 상태다. 미조사 검사를
  체인 맨 앞에 두면 시간역전(P2)이 적용되기도 전에 함정 후보가 전부 "보류"로 빠져 명시 기각을
  못 한다. 정비 시각(`maintenance_ts`)은 ⑤의 결정론 단계(pre-pass)가 수집한 사실이라 미조사
  여부와 무관하게 유효하므로, 시간정합(①)을 맨 앞에 둔다.
- **문제 2(보류가 채택 게이트보다 앞인 이유)**: ⑤ pre-pass가 suspect 장비를 못 찾으면
  `normal_ratio`가 `None`으로 남는다. 이때 근거없음·미조사 행이 반대근거 규칙에서 hard reject되면
  "안 봤다 ≠ 기각" 원칙(S2-6)이 깨진다.
- **선택**: `① 시간정합 → ②③ 보류 조건 → ④⑤⑥ 채택 게이트` 순서. 채택 후보(investigated=True)의
  결과는 재배치 전후로 불변이다 — 그들은 여전히 ④⑤⑥을 전부 통과해야 채택된다.
- **되돌릴 조건**: 규칙을 추가할 때 **"시간역전은 맨 앞 · 보류는 채택 게이트보다 앞"** 이라는
  순서 불변식을 유지해야 한다. `test_critic.py`가 이 순서를 3중으로 고정하고 있다.

### 4-3. "반박됨"과 "조사 안 됨"을 구분한다 (judge_unknown)

- **문제**: 조사하지 못한 후보를 반박된 후보와 똑같이 기각하면, 억울하게 죽는 후보가 생기고
  "채택 0건"이라는 판단 불가 상태가 부정확해진다.
- **선택**: 판정을 3분류로 나눠, 확인 못 한 것은 `judge_unknown`(보류)로 따로 뺀다. 보류는
  기각이 아니다 — "아직 모른다"는 정직한 상태다.
- **되돌릴 조건**: `반자동` 실제 조사 경로가 생기면 그 보류 토큰(SEMI_AUTO_PENDING)을 걷어낸다.

### 4-4. 표시 문구가 아니라 고정 코드로 판정을 전달한다 (API §2.7)

- **문제**: ⑦이 프론트 표시값(verdict 3종)을 자연어 사유 문구로 매칭하면, 문구를 조금만 고쳐도
  프론트 표시가 깨진다.
- **선택**: 기각·보류 행에 **고정 코드(`reject_token`)**를 부여하고, ⑦은 그 코드만 보고 매핑한다.
  `reject_reason` 문구는 순수 표시용이라 언제든 바꿔도 안전하다 — 그래서 #45의 영문화가 프론트를
  깨지 않았다.
- **대안과 기각**: 사유 문자열 직접 매칭 → 다국어·문구 수정에 취약.

### 4-5. 상관과 인과를 가른다 — 인과 서명 게이트 (P6, 0726)

- **문제**: 규칙 ①~⑤를 전부 통과해도 채택이 45건까지 나왔다. 더 심각한 건 **정답이 없는 배치에서도
  채택이 0이 되지 않는다**는 것이다(음성 시나리오 UNMATCHED-01/02에서 25·28건 채택 →
  `status=reviewed`로 틀린 원인을 자신 있게 제시). 채택 0이 안 되니 "채택 0 → 판단 불가"라는
  환각 억제 가드가 **구조적으로 발화하지 못했다.** 기획안이 내세운 차별점이 뚫리는 지점이다.
- **선택**: 채택 직전에 **두 조건의 결합**을 요구한다.
  - `commonality_ratio == 1.0` — 불량 로트 **전부**가 그 장비를 거쳤다(인과의 필요조건)
  - `direction_match is True` — 그 파라미터가 **KG가 예측한 방향으로** 실제 이탈했다(기전)
- **왜 결합이어야 하나 — 단일 신호는 둘 다 실측으로 기각됐다**:

  | 단일 안 | 왜 실패하나 | 실측 근거 |
  |---|---|---|
  | 공통률 단독 | 모든 로트가 지나가는 무관 장비가 1.0으로 통과 | LITHO-01이 CENTER-01/02/03에서 각 14건 채택. UNMATCHED-02는 CMP-01이 **우연히** 1.0 |
  | 특이성 단독 | 정답이 음수라 임계를 걸면 정답이 같이 죽음 | CENTER-03 정답 특이성 −0.43 |
  | 세기(지속률·이탈폭) | 정답보다 오답이 더 강한 경우가 흔함 | CENTER-01 정답 지속 28% vs 오답 100% |

  결합이 통하는 이유는 **두 조건이 서로 다른 종류의 오답을 막기** 때문이다. 상관만 완벽한 장비는
  방향이 막고(LITHO-01은 파라미터가 미동도 안 함), 신호만 강한 후보는 공통률이 막는다.
- **`is True`로 엄격 비교하는 이유**: `direction_match`는 `True`/`False`/`None` 3값이고, `None`은
  "KG가 방향을 안 줬거나 drift 자체가 없음"이다. `None`을 통과시키면 UNMATCHED-02의 최강 노이즈
  행(공통률 1.0 · 이탈 지속 99% · 특이성 0.76 — 어떤 세기 기준으로도 못 막던 행)이 살아난다.
- **검증**: ground truth 11개 전량 실행. **정답 시나리오 9/9 정답 보존**(게이트 통과분은 전부
  정답 장비 단일), **음성 2/2 완전 차단**(통과 0건 → `insufficient_evidence`), 총 채택 353 → 49건
  (86% 축소). 정답을 죽인 사례 0건. 상세는 `personalspace_rca/0725 work/hypo_critic_test_result.md` Part 5.
- **이 게이트가 하지 않는 일**: **같은 장비 안의 경쟁 원인은 못 가른다.** SCRATCH-01/02는 정답과
  경쟁자가 공통률·방향까지 동률이라 둘 다 통과한다(축소율 50~61%로 다른 시나리오의 85~96%보다 낮음).
  그건 ⑤의 특이성 타이브레이커(B2)가 랭킹으로 가른다 — **게이트는 아닌 것을 걸러내고, 랭킹이 고른다.**
- **되돌릴 조건**: `반자동` 실제 조사 경로가 붙으면 이 규칙을 tier 조건부로 바꿔야 한다 —
  정비·레시피 근거는 telemetry 방향이 없어 `direction_match`가 구조적으로 성립하지 않는다. 지금은
  반자동이 ③에서 먼저 보류로 빠져 여기 도달하지 않으므로 tier 커버리지 손실이 없다.

## 6. 튜닝 상수 · 매직넘버

| 이름 | 값 | 위치 | 근거 |
|---|---|---|---|
| 고정 사유 토큰 7종 | `P2_TIME_ORDER` · `P3_NO_COUNTER_EVIDENCE` · `P4_FAITHFULNESS` · `P5_NO_KG_MECHANISM` · `P6_NO_CAUSAL_SIGNATURE` · `SEMI_AUTO_PENDING` · `NOT_INVESTIGATED` | `critic.py` | ⑦ verdict 매핑 키 (API §2.7 — 자연어 매칭 금지) |
| `_COMMONALITY_MIN` | `0.999` | `critic.py` | ⑥ 인과 서명의 공통률 조건. 의미는 **"1.0"**(불량 로트 전부 통과)이고, 0.999는 부동소수 비교용 근사일 뿐 튜닝 여지가 아니다 |

- 임계값다운 임계값은 **없다.** `_COMMONALITY_MIN`은 등호(`== 1.0`)의 안전한 표현이고, 나머지
  규칙은 전부 부등호 비교(`정비시각 < 결함시각` 등)와 존재 검사(`None`인가)뿐이다.
- **여기에 "적당한 임계값"을 넣지 말 것**: 특이성·지속률·이탈폭으로 임계를 잡는 안은 전부 실측으로
  기각됐다(§4-5 표). 정답군의 값 범위가 오답군과 겹쳐 **분리하는 임계값이 존재하지 않는다.**

## 부록 B. 용어

| 용어 | 뜻 (Plain) |
|---|---|
| tier(검증등급) | KG가 후보마다 매긴 "어떤 도구로 확인 가능한가" 등급. `자동`(센서값)/`반자동`(정비·레시피)/`근거없음` |
| investigated | ⑤가 그 후보를 실제로 도구 조회했는지 여부(bool). False면 ⑥이 판단 보류 |
| judge_unknown(판단 보류) | 조사 못 했거나 확인 불가라 채택도 기각도 하지 않는 상태. **기각과 구분한다** |
| faithfulness firewall | ⑥이 fab을 다시 조회하지 않고 ⑤가 채운 `evidence`만 읽는다는 계약. 잘못된 LLM 서술이 판정에 못 들어오게 한다 |
| 함정(trap) | 상관관계는 높지만 실제 원인이 아닌 장비. 예: 불량 로트 전부가 지났지만 정비 시각이 결함보다 늦은 장비 — 상관은 있어도 시간상 원인일 수 없다 |
| reject_token | 기각·보류 사유를 나타내는 고정 코드. ⑦이 프론트 표시값을 정하는 유일한 키(문구가 아니라 코드로 매핑) |
| P2 / P3 / P4 / P5 / P6 | 규칙 체인의 사유 코드 번호. P2=시간역전, P3=반대근거 미수집, P4=faithfulness, P5=KG 근거없음, **P6=인과 서명 없음** |
| 인과 서명(causal signature) | "이 장비가 원인이라면 반드시 보여야 할 흔적" 두 가지의 결합 — ①불량 로트 **전부**가 그 장비를 거쳤고(공통률 1.0) ②그 파라미터가 **KG가 예측한 방향으로** 실제 이탈했다(`direction_match`). 상관(모든 로트가 지나감)과 인과를 가르는 최종 게이트 |
| 음성 시나리오(unmatched) | 결함은 실재하고 패턴도 우리 3종 안이지만, 시뮬레이터가 **원인을 주입하지 않은** 배치. 정답은 원인 이름이 아니라 **"판단 불가"** 자체다. 환각 억제를 재는 자리 |
